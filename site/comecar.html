01 — Baixar

Pegue o código. É só isso.

Não existe instalador nem cadastro. O Talho é software livre (GPL-3.0): “baixar” é trazer a pasta do projeto para o seu computador — de um destes dois jeitos.

  • semconta
  • semassinatura
  • seminstalador
  • semplano pago
  • semrecurso trancado

Clonar com git

O jeito mais prático, se você já usa git: para atualizar depois, basta um git pull dentro da pasta.

terminal
git clone https://github.com/fernangcortes/capiau-talho-v03.git
cd capiau-talho-v03

Baixar o ZIP

Sem git? Baixe o pacote do ramo main, descompacte onde quiser e abra a pasta capiau-talho-v03-main no terminal.

Baixar o ZIP (ramo main)

Vai pelo Python local? Tenha o git mesmo assim: o pip usa o git para instalar uma das dependências.

02 — Requisitos

O que a sua máquina precisa

Um computador comum dá conta: o Talho foi pensado para a CPU. E se você for de Docker, quase tudo desta lista já vem dentro do container.

Requisitos para rodar o CapIAu-Talho
ItemPrecisa deObservação
Python 3.12 (3.10+ compatível) Só no caminho Python local. O Docker já traz o 3.12.
FFmpeg e ffprobe Os dois no PATH Ter o ffmpeg.exe numa pasta qualquer não basta. O Docker já traz.
Memória (RAM) 8 GB 16 GB recomendados para acervos grandes.
Placa de vídeo (GPU) Não é necessária Se houver, o encode dos proxies usa NVENC, QSV ou AMF — e volta sozinho para a CPU quando precisa.
Docker Opcional — recomendado Traz Python 3.12, FFmpeg, PyTorch CPU, OpenCV e OpenTimelineIO prontos.
Git Para clonar No Python local, o pip também usa: o requirements.txt instala o CLIP direto do GitHub.
Disco Espaço para os proxies E para os modelos locais que você escolher baixar — de 25 MB a 6,4 GB cada.

Confira em 10 segundos

Rode no terminal. Cada linha deve responder com uma versão.

terminal
python --version   # 3.12 (ou 3.10+); no Linux: python3
ffmpeg -version
ffprobe -version
git --version
docker --version   # só se for usar Docker

Falta o FFmpeg? No Windows: winget install Gyan.FFmpeg. No Debian/Ubuntu: sudo apt install -y ffmpeg. Depois, abra um terminal novo.

03 — Instalar

Instale do seu jeito

O Docker é o caminho mais curto: um comando e tudo vem pronto, isolado do resto da máquina. Prefere o Python direto no computador? Também dá — e, no Windows, um script faz o trabalho pesado.

  1. 00:01

    Abra o terminal na pasta do projeto

    Com o Docker instalado e aberto, use o PowerShell (Windows) ou o terminal de sempre (Linux). Se você baixou o ZIP, a pasta se chama capiau-talho-v03-main.

    terminal
    cd capiau-talho-v03
  2. 00:02

    Crie o seu .env (pode ficar sem chaves)

    É ali que entram as chaves de API, se você quiser usar a nuvem — veja Chaves. O compose sobe mesmo sem ele, e o script do Windows faz esta cópia sozinho.

    PowerShell
    Copy-Item .env.example .env
    bash
    cp .env.example .env
  3. 00:03

    Deixe a porta só para você

    A API do Talho não tem autenticação, e o docker-compose.yml vem publicando a porta para a rede inteira. Abra o arquivo e troque a linha da porta para ela responder só nesta máquina:

    docker-compose.yml
        ports:
      - "8000:8000"             # antes: aberta para a rede
      - "127.0.0.1:8000:8000"   # depois: só nesta máquina
  4. 00:04

    Suba o Talho

    No Windows, o script faz tudo (e ainda cria o .env, se faltar). Em qualquer sistema, o comando do Docker é o mesmo. A primeira vez demora: o Docker baixa e monta Python 3.12, FFmpeg, PyTorch CPU, OpenCV e OpenTimelineIO. Para parar, Ctrl+C no terminal.

    PowerShell
    .\scripts\run-docker.ps1
    qualquer sistema
    docker compose up --build
  5. 00:05

    Abra no navegador

    Pronto. Suas mídias (watch/) e o banco, os proxies e os modelos (data/) ficam no seu disco, fora do container — nada se perde quando você reconstrói a imagem.

    Abrir http://localhost:8000
  1. 00:01

    Tenha o Python 3.12, o FFmpeg e o git

    O 3.12 é o recomendado (do 3.10 em diante funciona). O ffmpeg e o ffprobe precisam responder no terminal — e o git também, porque o pip instala uma dependência direto do GitHub. A lista completa está em Requisitos.

  2. 00:02

    Windows: deixe o script fazer tudo

    Na primeira vez, ele cria o .venv com Python 3.12 (usando o uv, se você tiver), instala o requirements.txt, copia o .env.example para .env e sobe o servidor em 127.0.0.1:8000. Nas próximas, só sobe.

    PowerShell
    .\scripts\run-local.ps1

    O PowerShell se recusou a rodar o script? Rode assim, do mesmo jeito que o criar-atalho.bat faz: powershell -ExecutionPolicy Bypass -File .\scripts\run-local.ps1

  3. 00:03

    Ou faça à mão

    Os mesmos passos, um a um. No Linux, troque o PowerShell pelo bash. O servidor sobe em 127.0.0.1:8000, o padrão do Uvicorn.

    PowerShell
    # ambiente virtual com Python 3.12
uv venv .venv --python 3.12
# ou: py -3.12 -m venv .venv

# dependências
uv pip install -r requirements.txt
# ou: .venv\Scripts\pip install -r requirements.txt

# servidor
.venv\Scripts\python -m uvicorn src.api.server:app --reload
    bash (Linux)
    # ambiente virtual (python3 --version: 3.12, ou 3.10+)
python3 -m venv .venv
source .venv/bin/activate

# dependências
pip install -r requirements.txt

# servidor
python -m uvicorn src.api.server:app --reload
  4. 00:04

    Abra no navegador

    Vai deixar o servidor rodando por horas no Windows? Use o lançador desgrudado, que não morre quando a janela do terminal fecha.

    Abrir http://localhost:8000

Windows: um atalho de duplo clique

Dê dois cliques em criar-atalho.bat, na raiz do projeto. Ele cria o ícone CapIAu na Área de Trabalho (e outro na própria pasta), que dá para fixar na barra de tarefas. Ao abrir, o atalho decide sozinho:

  1. O Talho já está no ar?só abre o navegador
  2. O Docker está aberto?sobe o container em segundo plano
  3. Nenhum dos dois?liga o Python local (.venv)

Em todos os casos, termina no navegador, em http://localhost:8000.

A porta fica só na sua máquina

A API do Talho não tem autenticação: quem alcança a porta usa o programa. O Python local já sobe em 127.0.0.1; no Docker, faça a troca do passo 3 (127.0.0.1:8000:8000).

Não exponha o Talho à rede local nem à internet sem autenticação e uma política de CORS restritiva.

04 — Chaves

Chaves de API: opcionais, suas e sob o seu controle

Dá para começar sem chave nenhuma. As chaves só ligam as partes em nuvem — que o provedor cobra por uso, direto da sua conta. O Talho não intermedeia nem cobra nada.

O .env é um arquivo de texto na raiz do projeto, com uma configuração por linha, no formato NOME=valor. Ele nasce como cópia do .env.example — os scripts do Windows fazem essa cópia sozinhos — e o Git o ignora de propósito, porque ele guarda segredos.

.env — exemplo
# na raiz do projeto · o Git ignora este arquivo
OPENROUTER_API_KEY=cole_sua_chave   # visão, títulos, temas, resumos, agente
ASSEMBLYAI_API_KEY=cole_sua_chave   # transcrição em nuvem
DEEPGRAM_API_KEY=                   # vazia = desligada

O painel tem prioridade. Chaves e modelos também se ajustam em Configurações › Modelos & Chaves, sem reiniciar — e o valor salvo no painel vale mais que o do .env. Lá, as chaves aparecem mascaradas.

Está tudo comentado no próprio .env.example.

Ponha um teto de gastos

No OpenRouter, defina um limite mensal em Settings › Limits (por exemplo, US$ 5). Na AssemblyAI, acompanhe o consumo no painel de faturamento.

Para ter uma ideia: o projeto foi desenhado para processar 20 horas de vídeo por menos de R$ 30. O áudio sobe como MP3 mono de 16 kHz, só as entrevistas vão para a transcrição (o B-roll fica de fora) e só um quadro por trecho vai para a visão.

Como o Talho economiza

Modelos gratuitos têm limite

No OpenRouter, os modelos :free aceitam 20 pedidos por minuto e 50 por dia — ou 1000 por dia, se a conta já comprou US$ 10. Em lotes grandes, eles também falham por timeout.

Por isso a visão usa um modelo pago por padrão e deixa o gratuito como reserva (VISION_MODEL_FALLBACK).

O que é o .venv-nemo e como montar

Canary, SenseVoice, Nemotron Diarization e pyannote rodam num segundo ambiente Python, fora do .venv principal, porque pedem versões de bibliotecas diferentes. No Windows, na raiz do projeto:

PowerShell
uv venv .venv-nemo --python 3.12
uv pip install --python .venv-nemo\Scripts\python.exe torch --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv-nemo\Scripts\python.exe -r requirements-nemo.txt

Montou em outro lugar? Aponte a variável CAPIAU_VENV_NEMO para a pasta do ambiente.

O que ainda não existe

Não há modelo local de linguagem nem de visão para descrever imagens, gerar títulos, temas e resumos ou conversar com o agente. Essas partes dependem de uma chave de nuvem (OpenRouter).

06 — Primeiros passos

Do zero ao primeiro corte, em 5 passos

O guia de 3 minutos da wiki, passo a passo. As ilustrações são estilizadas: evocam o programa, não são capturas de tela.

  1. 01

    Traga a mídia

    Coloque vídeos, áudios ou fotos na pasta watch/, dentro do projeto — ou aponte o seu HD externo pela interface. Nada é copiado nem modificado: o Talho guarda só o caminho de cada arquivo.

    No Docker, o container só enxerga as pastas montadas no compose (watch/ e data/). Para trabalhar direto num HD externo, o Python local é o caminho mais simples.

  2. 02

    Escaneie e indexe

    Clique para escanear a pasta watch/. O Talho lê os metadados com o FFprobe, gera proxies leves (720p) para o player, acha os cortes reais e indexa os quadros com o CLIP — tudo na sua CPU.

  3. 03

    Transcreva uma entrevista

    Abra a entrevista no player Source e use Transcrever Áudio (ASR). A fala aparece palavra a palavra — e, com a diarização, separada por pessoa. Sem chave de nuvem? Baixe um Whisper em Modelos locais.

  4. 04

    Monte

    Selecione um trecho no texto e tecle Shift+E: a fala vai direto para a timeline. Prefere pelo player? Marque I (entrada) e O (saída) e use Shift+E para adicionar ao fim, ou , para inserir na agulha.

    Todos os atalhos, com os 6 perfis (CapIAu, Kdenlive, Premiere Pro, DaVinci Resolve, Final Cut Pro e Custom), estão no guia de atalhos.

  5. 05

    Exporte

    Leve o primeiro corte em .otio para o Kdenlive 25.04+, que abre o arquivo nativamente, ou em .xml (FCP7) para o Premiere Pro ou o DaVinci Resolve. Também sai .edl — e o Talho renderiza MP4 pelo FFmpeg.

07 — Segurança

Três cuidados que valem para todo mundo

O Talho roda na sua máquina e confia em quem está nela. Por isso, mantenha-o só nela — e as chaves, só com você.

sua máquina 127.0.0.1:8000
rede e internet sem acesso

Só no 127.0.0.1

A API não tem autenticação: quem alcança a porta usa o programa. Deixe-a presa a esta máquina — 127.0.0.1:8000:8000 no compose; o Python local já sobe assim. Nada de expor à rede ou à internet sem autenticação e CORS restritivo.

O .env não sai daqui

Ele guarda segredos e já está no .gitignore. Nunca force a entrada dele num commit, nem cole chaves em issues, prints ou logs. Para mostrar a configuração a alguém, use o .env.example, com os campos vazios.

Troque as chaves de tempos em tempos

A cada 6 meses — ou na hora, se suspeitar de vazamento. Gere a nova no site do provedor, cole no painel ou no .env e revogue a antiga lá. No OpenRouter, dá também para restringir a chave e limitar os gastos.

08 — Problemas

Travou? Quase sempre é um destes

Os tropeços mais comuns, com a correção pronta para copiar. Não achou o seu? Abra um issue contando o erro — relato de instalação também ajuda o projeto.

O servidor não abre, e o erro fala em tokenizers ou transformers

Mensagem típica:

erro
ImportError: tokenizers>=0.22.0,<=0.23.0 is required for a normal functioning
of this module, but found tokenizers==0.23.1

Alguma instalação avulsa atualizou o tokenizers além do que o transformers aceita. Volte para a versão compatível, no ambiente do Talho:

terminal
pip install "tokenizers==0.22.2"

A 0.23.0 nunca saiu em versão final — o salto foi da 0.22.2 para a 0.23.1. Para não acontecer de novo, use um ambiente virtual só do Talho (o .venv): sem ele, qualquer projeto Python da máquina mexe nas dependências deste.

ffmpeg não é reconhecido como comando

O Talho chama o FFmpeg pelo nome, então ele precisa estar no PATH — ter o ffmpeg.exe numa pasta qualquer não basta. Sintoma típico: a ingestão até roda, mas nenhum proxy é gerado e a transcrição nunca começa. Confira onde ele está:

PowerShell
Get-Command ffmpeg
bash
ffmpeg -version

Não apareceu nada? Instale e abra um terminal novo:

PowerShell
winget install Gyan.FFmpeg
Debian/Ubuntu
sudo apt update && sudo apt install -y ffmpeg

Já tem o FFmpeg numa pasta? Adicione essa pasta (a que contém ffmpeg.exe e ffprobe.exe) às variáveis de ambiente do Windows. No Docker, nada disso: o FFmpeg já vem no container.

O servidor morre sozinho depois de horas rodando (Windows)

Se a janela do terminal que iniciou o servidor fecha, o Windows manda um CTRL_CLOSE_EVENT e o runtime MKL/PyTorch aborta — derrubando o servidor e os workers juntos. A saída é o lançador desgrudado, que sobe o servidor sem console nenhum (sem janela, não há o que fechar):

PowerShell
.venv\Scripts\python scripts\launch_detached.py .venv\Scripts\python.exe -m uvicorn src.api.server:app --host 127.0.0.1 --port 8000 --stdout logs\servidor.log --stderr logs\servidor-erros.log

Ele mostra o PID do servidor, e a saída vai para os dois arquivos em logs\. Para encerrar depois: Stop-Process -Id seguido desse número.

A busca não retorna nada, ou avisa que o índice está indisponível

O banco vetorial (Qdrant) fica em data/qdrant.db. Se o acervo foi indexado antes de uma troca de EMBEDDING_MODEL, os vetores antigos não conversam com as buscas novas. Reindexe, com o Talho no ar:

bash
curl -X POST http://localhost:8000/api/search/reindex
PowerShell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/search/reindex
A exportação falha, ou avisa sobre o worker de exportação

Mensagem típica no console:

console
[EXPORT] Aviso: 'opentimelineio' sem wheel neste Python; exportacao usara o worker
do venv 3.12 (data/venv312) se ele existir.

A exportação depende do opentimelineio e de dois adaptadores que não são opcionais: sem o otio-fcp-adapter não sai XML; sem o otio-cmx3600-adapter não sai EDL. Instale os três no ambiente do Talho:

terminal
pip install opentimelineio otio-fcp-adapter otio-cmx3600-adapter

Num Python sem wheel do opentimelineio (como o 3.14), crie o interpretador auxiliar 3.12 que a exportação procura sozinha:

PowerShell
uv venv data/venv312 --python 3.12
uv pip install --python data/venv312/Scripts/python.exe opentimelineio otio-fcp-adapter otio-cmx3600-adapter python-dotenv
As análises de visão falham com timeout ou erro 504

Costuma acontecer com modelos gratuitos (:free) sob carga: o gateway do OpenRouter espera o modelo responder e desiste. Use um modelo pago como VISION_MODEL (troque no painel de configurações) e deixe o gratuito só como reserva — é a configuração padrão, justamente por isso:

.env
VISION_MODEL=google/gemini-2.5-flash
VISION_MODEL_FALLBACK=nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free
“Address already in use”: a porta 8000 está ocupada

Outro programa já está ouvindo na porta 8000 — muitas vezes, o próprio Talho, aberto em outra janela ou no Docker. Se ele já está no ar, é só abrir http://localhost:8000. Se a porta está com outro programa, suba o Talho (Python local) em outra porta e abra http://localhost:8080:

PowerShell
.venv\Scripts\python -m uvicorn src.api.server:app --port 8080 --reload
Funciona sem internet?

As partes locais, sim — depois de instaladas e com os modelos que você escolheu já baixados: catalogar, gerar proxies, achar cortes, buscar por imagem, agrupar rostos, medir e tratar áudio, transcrever com o Whisper, montar e exportar.

Descrição visual, títulos executivos, temas, resumos e o agente dependem de uma chave de nuvem — e, portanto, de internet. A transcrição em nuvem (AssemblyAI ou Deepgram) e o Auphonic também.

Mais respostas no README e na wiki. Nada resolveu? Abra um issue com a mensagem de erro e o que você já tentou.
